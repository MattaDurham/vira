# Vira modules

Vira > Modules

This folder is the map of the code, laid out the way the app is laid out:
one folder per module (a window, or the layer underneath every window), one
folder inside it per submodule, and in every folder a `README.md` that says
what lives there and a `module.json` that lists it. It is the density ladder
`AGENTS.md` already uses, carried into the code: each page holds only what
you need to choose the next page, and the last page holds everything.

## How to use it

You are here. Pick the module below that owns what you are changing, open
its README, pick the submodule, open that README. Its generated block lists
every file the submodule owns with one line on what each is, the routes it
serves, the stores it keeps under `data/`, what it reads from and what it
feeds (each a link to that submodule's page), and the System Map records
that describe it. Then open the files.

One command does the same walk and adds the full module docstring of every
server file:

    python -m server.moduletree brief work/automations

`where <path>` names the submodule that owns a file; `tree` prints the whole
tree with counts.

## How it stays true

`python -m server.moduletree check` fails when any tracked file under
`server/`, `static/`, `tests/`, `scripts/`, `android/`, `bridge/`,
`fixtures/`, `walkthroughs/` or `walkthrough_anon/` is owned by no submodule
or by two, when a link points at a submodule that does not exist, or when a
README's generated block no longer matches the manifest and the code.
`tests/test_moduletree.py` runs it on every PR. A new file is placed by
adding it (or a glob that covers it) to one `module.json`, then
`python -m server.moduletree index --write` refreshes the READMEs.

The prose above each generated block is written by hand and never touched
by the tool. The manifest's `summary` is the one line the parent index shows.

## Moving code

Today the tree describes where things belong; the files still live in
`server/`, `static/`, `tests/` and `scripts/`. Gathering a submodule's files
under its folder is a separate, per-submodule change: `python -m
server.moduletree plan work/automations` prints the `git mv` list, and the
move also has to turn the submodule's routes in `server/main.py` into a
router of its own (the pattern `genreroutes.py`, `imageatlasroutes.py` and
`resumeviewroutes.py` already follow) and rewrite the `from . import x`
lines and static paths that point at the moved files. Do one submodule per
branch; the suite and `check` say when it is whole.
